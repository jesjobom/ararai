# Design

The approximate input budget reserves the configured output allowance plus an additional 10% of total context capacity (rounded up) before selecting history. The boundary metadata and the actual prompt use this same budget; the margin is a best-effort allowance for token-estimation error, not a native tokenizer guarantee. If required system/current content alone exceeds the budget, omit all historical turns without pretending that trimming history can make the input safe.

The coordinator currently reads at most 512 recent stored messages and `PromptContextBuilder` walks backward, accepting each message that fits its approximate character budget. This can select noncontiguous messages and even split a user/assistant exchange. Replace that policy with a contiguous suffix of eligible **user turns** (a user message and its associated assistant message, if one exists). Keep the system instruction, current request, and configured output reserve outside the droppable history. If the newest historical turn does not fit, include no earlier history; do not silently fill the gap with older short turns. Preserve existing audio-transcription eligibility and historical-media replay rules.

The fixed 512-message read must not become a hidden permanent inclusion boundary when the configured context is increased. Read stored history in bounded pages until the context boundary is resolved, without loading unbounded data on the main thread. Return inclusion metadata (selected canonical message IDs or oldest included turn plus whether older eligible turns exist) alongside the projected prompt, so rendering and generation use the **same** decision rather than separate estimates. If a newly projected suffix differs from a retained LiteRT-LM transcript, the existing compatibility check must discard and rehydrate native state. Never edit or delete excluded stored messages.

Render a subtle, accessible, single divider immediately before the oldest included historical turn when excluded older turns are already loaded in the normal Chat timeline. It should say, for example, “Earlier messages are outside the context of the next response”; avoid an error-red marker. If the actual boundary is above the currently loaded UI page, show a compact “Some older messages are outside context” indication near Load older, replacing it with the exact divider when that page is loaded. The marker is derived, not persisted as a message. It recalculates when the selected model, effective context, effective prompt/memory, draft request, or conversation changes. During an in-flight response, freeze the boundary for that submitted request; after completion, calculate it for the next one. Clarify that this indicator concerns bounded textual history, not historical media eligibility.

Tests should cover a recent long turn followed by older short turns, incomplete/cancelled turns, no fitting history, context increase/decrease, pagination, Voice Chat projection, and retained-conversation reuse. Device validation should verify that the divider moves without changing or losing stored chat messages.

# Design

The LiteRT-LM bridge can read the cumulative native conversation token count at completion, but does not report why generation stopped. The benchmark's last-prefill and last-decode counters cover only the last phase and cannot diagnose context exhaustion after tool calls. Chat compares the cumulative count to the effective total-context setting only after a terminal turn with no final answer. Within eight tokens of capacity, the stored reason is `ContextCapacityLikely`; this is a heuristic, not a native stop code. Otherwise, a completed tool event yields `AfterToolCall`, describing only the observed sequence, not the stop cause. Missing or lower metrics with no tool event leave the reason unspecified. The banner maps those cases to localized, actionable copy. Persisting the reason avoids changing historical messages when the user's context setting changes later.

For older incomplete messages without a stored reason, existing attached tool sources can still support the `AfterToolCall` explanation. This is a presentation-only fallback; no historical message is rewritten.

The terminal-status notice is placed after partial reasoning, answer text, and sources. Chat follows the end of the latest message, so the notice remains visible without duplicating it beside the input.

Non-blank output needs a different rule from a genuinely absent final answer. At the terminal callback, a cumulative native count at or above the configured limit sets a persisted `PossiblyIncomplete` status and the context-capacity reason while retaining the generated text. A count below capacity or unavailable leaves a non-blank response complete. `PossiblyIncomplete` remains reportable as generated text. Its yellow notice says the output may be incomplete or unreliable; it does not claim a native stop reason. Context-capacity notices for blank responses also use yellow, while unrelated incomplete-response errors retain the error color. This is a diagnostic signal based on the post-generation count, not a fix for prompt-budget estimation.
The native count travels as a separate generation event so a failure to read optional benchmark information cannot suppress the capacity warning.

The cancellation button and navigation away from Chat have a distinct, app-observed stop path. They persist `Cancelled` on the active assistant message before finalizing it, preserving any partial output. If audio transcription has not created an assistant message yet, cancellation creates one for the status. Reopening preserves explicit cancellation; legacy blank messages without this status remain ambiguous and are not relabelled as user-cancelled.

The web-search adapter keeps passing through the provider's normalized evidence (bounded by the existing 1,800-character contract). A fixed 600-character model-specific cap was tested on the SM-S901E and removed: although it allowed one previously failing turn to finish, it discarded evidence regardless of available context. This change reports likely exhaustion to the user instead of silently reducing retrieval quality or retrying generation.

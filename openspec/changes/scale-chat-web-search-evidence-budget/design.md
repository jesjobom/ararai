# Design

Resolve the effective context-token setting for the selected Chat model at the start of a generation request and pass a per-invocation evidence policy to the model-facing web-search adapter. Calculate `floor(contextTokens * 0.25) * 4` characters. The budget applies independently to each of the at most two `web_search` calls in a user turn; it is not depleted across calls or subsequent turns. Do not inspect or estimate remaining context. This is an explicit quality-versus-capacity tradeoff: a large tool result can still contribute to native context exhaustion, which the existing incomplete-response path reports.

Count the **entire serialized model-visible success result**, including its JSON framing, untrusted-reference preamble, source titles, URLs, and excerpts. Provider responses remain bounded and validated before normalization. After ranking and deduplication, include up to three distinct HTTPS sources and up to two focused excerpts per source, using Unicode-safe cuts for the final excerpt if necessary. Never claim a source as included when no excerpt from it reached the model; return a controlled no-results outcome if even one meaningful source cannot fit. Keep source metadata aligned with the evidence actually returned. The fixed 500-character excerpt ceiling must not silently cap Chat output at larger context settings; any provider request-level excerpt cap should be reviewed alongside the adapter.

The provider chain and focused-evidence normalizer are currently shared with widget `web_search_content`. Make evidence limits an explicit caller/consumer policy rather than changing shared constants globally. Widget calls retain their present 1,800-character envelope, 500-character excerpts, and contracts; `web_search_top_results` is separate and unchanged. No vendor credential or raw provider protocol enters the model result.

The four-characters-per-token conversion is an approximation, not a tokenizer guarantee. Tests should cover multiple context sizes, JSON escaping and Unicode boundaries, multiple calls in one turn, and unchanged widget outputs. Device validation should compare the serialized Chat tool-result size and confirm that a context-exhaustion failure remains visible rather than causing a silent retry or truncation beyond the declared policy.
